# 图片编辑工作台交互修复设计

日期：2026-07-30

## 目标

修复创作台文字选择、参考图预览、图片粘贴路由、图片角色混用、右侧模板、滚动条和添加文字体验，并把“超分”入口改名为“放大/去水印”。

## 已确认问题与根因

1. 创作台根节点允许选中文字，但按钮被全局 `user-select:none` 覆盖，分类、模板和按钮内说明无法复制。
2. 生成结果已有灯箱和 ESC 关闭逻辑，上传的源图/参考图只是静态 `<img>`，没有共用灯箱入口。
3. 提示词输入框粘贴图片时，`handlePromptImagePaste` 无条件把模式切到 `image`，导致图片编辑被错误跳转。
4. 图片编辑复用普通多参考图列表，虽有 `image/background/garment/face` 角色，但没有明确的“主图/专用参考图”双槽模型，粘贴也没有按当前编辑动作分配角色。
5. 图片编辑仍把内部执行提示当成可见提示词模板。后端已经按 operation 在执行指令顶部注入固定约束，前端无需展示或重复拼接。
6. 参数区使用系统可见滚动条，上传按钮使用可换行 flex，窄宽度下会挤压变形。
7. 文字坐标使用数字输入，用户看不到实际位置。后端 `text_overlay` 是确定性本地渲染，不调用图片模型，前端应提供画布拖动和即时预览。

## 交互设计

### 文字选择

- 创作台的标题、说明、状态、参数文字、模板文字可拖选复制。
- 图片、画布、滑块和纯图标仍保持不可选，避免拖动交互冲突。

### 图片放大

- 上传主图、普通参考图、背景、服装和人脸缩略图都可点击打开统一灯箱。
- 点击遮罩背景、关闭按钮或按 ESC 关闭。
- 删除按钮阻止事件冒泡，不会误打开灯箱。

### 粘贴路由与双图槽

- 文生图粘贴图片：切换到图生图，保持现有行为。
- 图生图、批量和放大/去水印粘贴图片：留在当前分类。
- 图片编辑粘贴图片：始终留在图片编辑。
- 换背景、换衣、换脸固定显示横向双槽：左侧“上传主图”，右侧“上传参考图”。
- 第二槽根据动作绑定 `background`、`garment` 或 `face`，最多一张主图和一张专用参考图。
- 去背景、加文字只需要主图，不显示无意义的第二槽。
- 切换编辑动作时保留主图，清除与新动作角色不匹配的旧辅助图。

### 右侧素材模板

- 图片编辑不再显示可见的内部提示词模板。
- 换背景显示背景模板，换衣显示服装模板，换脸显示人脸模板。
- 模板复用随前端部署的本地素材，点击后直接写入对应辅助角色，不覆盖主图。
- 用户提示词框只保存用户自己的补充要求；操作固定约束继续由后端按 operation 置顶注入。

### 文字编辑器

- 选择“加文字”并上传主图后，预览画布直接显示原图和文字选框。
- 文字可在图片上拖动；拖动结果转换为原图像素坐标并发送 `position=custom + x/y`。
- 左侧提供文字内容、字体（无衬线/衬线）、字号滑块、颜色和九宫格快捷定位。
- 不再暴露 X/Y 数字输入。
- 文字选框、拖动手柄和即时预览属于前端编辑辅助；最终结果仍调用后端确定性 `text_overlay`，不调用图片模型。
- 当前后端契约没有 `fontWeight`、描边或文字底框字段，前端不发送虚假字段；本轮实现可视化选框和现有契约支持的字体、字号、颜色、位置。

### 布局

- 参数区继续支持鼠标滚轮/触控滚动，但隐藏滚动条。
- 双上传槽固定两列，不因宽度缩成竖排或把按钮挤变形。
- “超分”中文入口和标题改为“放大/去水印”，接口 operation 不变。

## 数据流

1. UI 根据当前 mode/action 计算允许的素材槽和角色。
2. 上传、粘贴、模板选择统一进入角色化素材更新函数。
3. 提交时继续发送 `operation + options + sourceImages.role`。
4. 用户提示词保持原文；后台执行约束由现有后端 `BuildExecutionPrompt` 负责。
5. 文字拖动只更新 `textPosition/textX/textY`，请求仍符合 `2026-07-30.image-operations-v2.6`。

## 测试要求

- 纯函数测试：图片编辑粘贴角色、最多两张、切换动作清理旧角色、模板角色。
- 组件测试：双槽横排、空槽、上传标签、缩略图灯箱、图片编辑模板替换、隐藏提示词模板、文字坐标不显示。
- 交互测试：参考图点击放大、ESC 关闭、文字拖动坐标换算。
- 回归：文生图粘贴仍切图生图；图片编辑粘贴不切换；任务分类隔离不变。
- 完整运行 lint、146+ 测试、build、TypeScript、git diff --check，并做 Live 浏览器验收。
